A proxy should absorb abusive load before it reaches the backend: throttle
per client, key that throttle on the real connection peer (not a
client-supplied header), and cap request sizes. These checks measure those
properties with small, bounded probes.

<Aside type="caution">
  These checks are part of the v0.4 aggressive suite and only run with
  `--aggressive`. The bursts are deliberately small (≈20–30 requests) — they
  measure throttling behaviour, not a flood.
</Aside>

| Check ID | Title | CVSS 4.0 | CWE | OWASP |
| --- | --- | --- | --- | --- |
| `ratelimit.missing_throttling` | No Per-Client Request Throttling at the Proxy | 5.3 | [CWE-770](https://cwe.mitre.org/data/definitions/770.html) | API4:2023 |
| `ratelimit.spoofed_ip_bypass` | Rate Limit Bypassed via Spoofed Client-IP Header | 6.9 | [CWE-770](https://cwe.mitre.org/data/definitions/770.html) | API4:2023 |
| `ratelimit.oversized_header` | Oversized Request Headers Accepted Without a Limit | 5.3 | [CWE-770](https://cwe.mitre.org/data/definitions/770.html) | API4:2023 |

## `ratelimit.missing_throttling`

Sends a small burst from one client and reports when none of the requests
is throttled. Informational-to-low: throttling at the backend or an
external layer is not visible to a single-client burst.

**Remediate:** enforce per-client request rate limiting at the proxy
(e.g. nginx `limit_req`, an API gateway plan).

## `ratelimit.spoofed_ip_bypass`

For a proxy that does throttle, drives it into throttling, confirms a plain
request is still throttled, then flips the response back to success by
rotating a spoofed IP in `X-Forwarded-For`, `X-Real-IP`, `True-Client-IP`,
`X-Client-IP`, or `X-Forwarded`. A header that resets the limit is a
confirmed bypass; the check skips when no throttling is observed.

**Remediate:** key rate limiting on the real connection peer, and only
trust a client-IP header when it arrives from a known, trusted upstream
(see the Client-IP & Header Trust Boundary checks).

## `ratelimit.oversized_header`

Sends one request with a single 128 KiB header and flags acceptance rather
than a 431/400/413 rejection — a proxy with no header-size cap lets a client
force large per-request allocations.

**Remediate:** set conservative request-header size limits (nginx
`large_client_header_buffers`, Apache `LimitRequestFieldSize`).

## Not yet covered

Slowloris / slow-body resistance and connection/keepalive limits under load
(checklist items 3 and 5) are genuine denial-of-service tests that can
degrade a live target even when bounded; they are intentionally left to a
dedicated, separately gated capability rather than running under
`--aggressive`.
